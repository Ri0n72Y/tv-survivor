# Exploration Design

> 状态：骨架 / 待填充。
>
> 本文件描述当前首个世界泡的阵列探索设计。它只整理已经确认的玩法骨架，并为三层 / 三大关预留稳定的内容槽位。尚未确认的主题、剧情、具体房型、事件、怪物与奖励不在本版擅自补全。

## 1. 设计目标

当前世界泡用于验证和展开游戏的核心阵列探索体验：

- 玩家在固定的关卡骨架中移动与判断；
- 探索持续累积侵蚀；
- 地图事件提供信息、资源、风险、净化、剧情与局部玩法入口；
- 玩家通过路线和事件管理侵蚀与其他资源；
- 安全屋提供明确的无侵蚀休整空间；
- 事件和部分房间组合产生重复探索变化；
- 三层分别形成独立主题、空间特色和内容记忆点；
- 阵列本身承担玩法、演出和气氛表达，而不是仅作为菜单。

## 2. 基础探索循环

```text
进入当前层
    ↓
读取可见阵列与有限信息
    ↓
移动 / 调查 / 选择路线
    ↓
累积侵蚀
    ↓
触发地图事件
    ├─ 资源 / 奖励
    ├─ 净化 / 延缓侵蚀
    ├─ 剧情 / 演出
    ├─ 机关 / 地图状态变化
    ├─ 安全屋 / 休整
    └─ 局部玩法
    ↓
获得结果并更新阵列状态
    ↓
继续深入 / 绕行 / 休整 / 结束阶段
```

核心判断应持续围绕：

- 当前路线会带来什么；
- 当前侵蚀是否还能承受；
- 是否值得绕路获取净化或资源；
- 是否要冒险进入未知/高收益区域；
- 是否应该先进入安全屋整理，再继续推进；
- 当前局部玩法的收益与成本是否值得承担。

## 3. 侵蚀

### 3.1 职责

侵蚀是阵列探索的基础压力资源。

它需要同时承担：

- 限制无限探索；
- 让路线长度产生真实成本；
- 赋予净化事件与安全屋地图价值；
- 形成“继续深入还是止损”的判断；
- 为事件、视觉异常和关卡演出提供统一状态来源。

### 3.2 当前确认

- 玩家探索过程中会累积侵蚀；
- 某些事件可以清除或延缓侵蚀；
- 安全屋中不累积侵蚀；
- 侵蚀不应只是隐藏计时器或纯数值惩罚；
- 高侵蚀可以成为事件条件、地图状态或特殊内容的触发依据。

### 3.3 待设计

- 侵蚀按移动、事件、时间还是多种行为累积；
- 是否存在阶段阈值；
- 阈值产生什么可读后果；
- 是否允许超过安全值继续探索；
- 侵蚀与局部玩法是否互相影响；
- 层间是否保留、部分保留或重置。

## 4. 净化与侵蚀管理

净化不只是一种“回血药”，而应形成路线与事件选择。

后续内容至少可以从以下职责中设计：

- **直接净化**：减少已有侵蚀；
- **延缓**：若干步/事件内降低侵蚀累积；
- **交换**：消耗其他资源换取净化；
- **风险净化**：承担事件或局部玩法换取更强净化；
- **条件净化**：满足特定探索条件后清除侵蚀；
- **异常利用**：高侵蚀时获得特殊内容或收益，同时继续承担风险。

具体事件之后按每层主题填充。

## 5. 安全屋

安全屋是阵列中的特殊空间，而不是脱离地图的通用菜单。

基础职责：

- 进入后暂停侵蚀累积；
- 提供明显的节奏缓冲；
- 允许玩家提交部分探索资源；
- 允许一定程度的升级、整理或补给；
- 可以承载固定信息、剧情、记录或装置交互；
- 作为路线规划中的稳定锚点。

待讨论：

- 每层是否固定一个安全屋；
- 是否存在隐藏/条件安全屋；
- 安全屋是否完全安全；
- 可以提交哪些资源；
- 提交资源是否意味着即使后续失败也能保留；
- 升级是本次探索临时升级还是全局升级。

## 6. 地图结构与随机原则

### 6.1 主地图骨架

三大关的主形状由关卡设计决定，不进行完全程序随机。

主地图骨架负责：

- 主题空间印象；
- 关键路径；
- 分支与回环；
- 安全屋位置；
- 阶段目标；
- 机关关系；
- 固定演出；
- 关卡特有的空间玩法。

### 6.2 重复探索随机

重复探索主要随机：

- 普通事件内容；
- 事件在允许位置中的分布；
- 资源和奖励；
- 部分风险；
- 局部玩法组合；
- 可选支路内容；
- 特殊房间模板。

### 6.3 特殊形状随机

某些内容可以主动把“空间变化”作为规则。

此时允许从 **预先设计的形状/房间模板池** 中随机选择，而不采用无限制的任意拓扑生成。

这类形状随机应有明确设计目的，例如：

- 迷路；
- 空间错位；
- 追逐；
- 侵蚀导致的阵列异常；
- 特殊奖励房；
- 隐藏区域。

## 7. 地图事件

事件是重复探索内容的主要随机单位，也是剧情和世界泡内容进入阵列的主要媒介。

建议后续按职责组织事件池，而不是先按大量独立事件堆积：

| 类型 | 主要作用 |
|---|---|
| 信息事件 | 揭示地图、风险、目标或其他事件信息 |
| 资源事件 | 获得、交换或损失资源 |
| 侵蚀事件 | 增加、降低、延缓或利用侵蚀 |
| 路线事件 | 开门、封路、传送、改变连接或开启支路 |
| 局部玩法事件 | 展开当前世界泡的战斗/其他玩法 |
| 叙事事件 | 表达剧情、角色、世界泡状态或演出 |
| 收藏事件 | 获得可带回的收藏品、记录或特殊成果 |
| 特殊规则事件 | 仅属于某层或某一特定房型的规则 |

事件可以同时承担多个职责，但应有一个主要目的。

## 8. 阵列演出

阵列是正式的演出空间。

可使用的表达手段包括：

- 节点图像与状态变化；
- 整张阵列的亮度、噪声、扫描与失真；
- 节点突然出现、消失、错位或替换；
- 玩家移动规则暂时变化；
- 可见范围变化；
- 假节点、异常节点或错误显示；
- 音效、文字、信号和节奏变化；
- 固定地图形状本身形成叙事或恐怖意象。

视觉基调采用项目自己的 **赛博显像管 / CRT 观测界面**。关卡主题可以改变信号、显示和异常表现，但仍保持统一设备语言。

## 11. 三层之间的推进

三层不应只是难度数值递增。

后续设计时至少检查：

1. 第一层是否建立基本探索语言；
2. 第二层是否利用玩家已掌握的规则制造明显变化；
3. 第三层是否组合、扭曲或反转前两层学到的内容；
4. 侵蚀管理是否随层级产生新的判断，而非单纯涨得更快；
5. 阵列演出和视觉是否形成递进；
6. 三层是否各自存在可以单独被记住的空间场景；
7. 重复探索时，随机事件是否改变路线判断而不破坏关卡主题。

## 12. 当前优先填充顺序

后续不需要一次写完整个世界泡，按以下顺序逐步填充：

1. 确定三层各自的一句话主题与核心情绪；
2. 确定三层主地图形状与独有地图机制；
3. 确定侵蚀基础规则；
4. 确定安全屋在三层中的位置与功能；
5. 为每层设计少量代表性固定事件；
6. 建立第一批可重复随机事件池；
7. 再填类幸存者房间、怪物、奖励和收藏；
8. 最后补充演出、隐藏内容与特殊随机形状。

这一顺序优先验证阵列探索本身，而不是先靠大量局部战斗内容撑起关卡。
