# Game Concept

> 状态：讨论中。
>
> 本文件描述 **tv-survivor 想成为怎样的游戏**。Design 先于版本 Requirement：Design 可以保留尚未进入当前开发范围的设想；Requirement 在设计收敛后，从 Design 中抽取当前版本要实现的 Scope。
>
> 当前讨论只确认游戏概念与玩法关系，不提前把未来扩展方向实现成通用框架。

## 1. 核心概念

这是一款以 **阵列式探索** 为核心 Gameplay 的游戏。

玩家拥有一台能够观测不同“世界泡”的装置，并通过自动探索机器人进入这些世界泡。玩家在阵列化的结构界面中读取有限信息、移动、调查、触发事件、管理资源与风险，并在必要时展开世界泡对应的局部玩法。

玩家探索不同世界泡，并把其中获得的收藏品、记录与其他成果带回自己的据点。

阵列探索是游戏长期稳定的核心。具体世界泡中的战斗、牌组、撤离或其他玩法属于阵列探索过程中被展开的 **局部玩法**，不等同于游戏本体。

## 2. 玩家身份与最低限度世界设定

当前项目只需要足以支撑玩法的世界设定：

- 主角拥有一台世界泡观测装置；
- 主角能够派遣自动探索机器人进入被观测的世界泡；
- 不同世界泡可以拥有不同空间结构、规则、事件与局部玩法；
- 探索可以带回收藏品及其他成果；
- 主角所在世界、世界泡来源、装置原理等内容暂不展开，除非具体玩法需要。

世界观服务于玩法，不要求先建立完整宇宙史、势力史或社会结构。

“世界泡观测装置 + 自动探索机器人”在概念上可参考《绝区零》中 HDD 与代理人之间的玩法关系，但本项目不要求复制其世界设定。

## 3. 核心 Gameplay：阵列探索

阵列探索是玩家主要进行判断和操作的结构层。

主要设计参考为《绝区零》的阵列探索模式，次要参考为《魔塔》式格子探索。

核心关注点不是单纯“走格子”，而是让每一次移动或操作推进局势。一次有意义的行动至少应改变以下一项：

- 信息；
- 资源；
- 风险；
- 路径或空间结构；
- 当前状态；
- 事件或叙事上下文。

阵列空间可以承载：

- 路径选择；
- 隐藏与揭示；
- 资源获取与消耗；
- 机关与状态变化；
- 随机或条件事件；
- 局部玩法入口；
- 撤退、转向与止损；
- 世界泡自身的特殊规则。

阵列探索不能退化为“在真正玩法之间赶路”的菜单。即使没有进入局部玩法，阵列层本身也应持续产生判断与后果。

## 4. 局部玩法

阵列探索过程中可以展开不同类型的局部玩法。

局部玩法是世界泡规则的一部分，而不是阵列系统的固定组成。

当前版本主要实现 **类幸存者** 玩法，但设计上不能假设所有世界泡都会通过类幸存者战斗解决事件。

概念上，阵列层只需要知道：

1. 当前事件需要进入某种局部玩法；
2. 世界泡决定使用哪种玩法及其输入条件；
3. 局部玩法结束后返回结果；
4. 结果继续改变阵列探索状态。

具体的软件接口、数据契约和模块边界属于后续 System Design 与 Spec，不在 Game Concept 中提前设计。

## 5. 当前主要世界泡：类幸存者原型

当前开发阶段首先制作一个以类幸存者玩法为主要局部玩法的世界泡。

### 5.1 目的

这一世界泡承担两个目标：

1. 验证阵列探索与局部玩法展开、返回之间的完整循环；
2. 做出一套本身具有足够可玩性的类幸存者原型。

### 5.2 玩法参考

类幸存者部分当前主要参考《崩坏：星穹铁道》活动“银河球棒侠传说”的体验方向，并可在原型阶段参考其武器、怪物、成长节奏与构筑关系来快速验证玩法。

这些参考用于原型与玩法研究，不意味着它们自动成为项目长期原创内容或永久数据结构。

### 5.3 剧情包装

这一世界泡当前采用轻量、服务玩法的剧情设定：

> 某个“愚者”随手丢弃了一份未采用的废案，废案漂流在宇宙中并形成一个可被观测的世界泡。

该世界泡可以结合对“模拟宇宙”等作品形式的轻量 neta，但剧情不需要在当前阶段扩展为完整世界观。

### 5.4 当前循环

概念级循环为：

```text
观测并进入世界泡
        ↓
在阵列中探索
        ↓
获取信息 / 资源 / 状态变化
        ↓
触发局部事件
        ↓
必要时展开类幸存者玩法
        ↓
局部玩法结算
        ↓
结果返回阵列
        ↓
继续探索 / 改变路线 / 撤离
        ↓
带回本次探索成果与收藏品
```

类幸存者玩法目前是主要实现内容，但不应吞并阵列探索成为整个游戏唯一循环。

## 6. 世界泡作为内容与玩法容器

“世界泡”用于解释为什么不同探索可以拥有显著不同的：

- 地图结构；
- 地图生成方式；
- 视觉主题；
- 事件规则；
- 资源与风险；
- 局部玩法；
- 收藏品与叙事碎片。

长期可以通过新增世界泡扩展游戏，而不要求所有世界泡共享同一种局部玩法。

未来候选方向包括但不限于：

- 随机地图生成的阵列探索；
- 打牌爬塔；
- “球比伦式肉鸽”；
- 类《小丑牌》的冒险/构筑玩法；
- 搜打撤；
- 其他能够和阵列探索形成输入—结算—回流关系的玩法。

这些目前都是未来 Design 空间，不属于当前版本 Requirement，也不因此要求现在实现一套支持所有玩法的通用引擎。

## 7. 长期稳定与可替换的部分

### 7.1 长期稳定的核心

目前认为应长期保持稳定的概念包括：

- 通过观测装置选择和进入世界泡；
- 使用自动探索机器人执行探索；
- 阵列探索是主要结构 Gameplay；
- 阵列中的行动会改变信息、资源、风险或状态；
- 世界泡可以触发局部玩法；
- 局部玩法结果会返回阵列；
- 一次探索能够带回收藏品或其他成果；
- 不同世界泡可以承载不同玩法规则。

### 7.2 可替换内容

以下内容不应在 Game Concept 层固定为整个游戏的永久规则：

- 类幸存者是否是局部玩法；
- 战斗是否存在；
- 当前武器、怪物、被动与成长数据；
- 当前地图是否为树状、方格或其他拓扑；
- 当前节点种类；
- 当前世界泡剧情；
- 当前资源名称；
- 当前原型场景与代码结构。

## 8. 设计原则

### 8.1 阵列探索优先

评估新增内容时，首先判断它如何丰富阵列探索中的信息、决策、路径、状态或风险，而不是先增加新的局部小游戏。

### 8.2 局部玩法必须回流

局部玩法不能成为与阵列无关的独立关卡。它至少需要接收来自阵列的上下文，并返回能够改变后续探索的结果。

### 8.3 世界泡允许变化，但不提前泛化实现

设计上承认未来会存在完全不同的世界泡和玩法；工程上仍只为当前被 Requirement 选中的玩法建立必要边界。

“未来可替换”不等于“现在做万能框架”。

### 8.4 世界观服从玩法

只有当一个设定能够解释、强化或组织玩法时，才需要在当前阶段展开。

项目不以先完成完整世界观设定为前提。

### 8.5 原型允许直接参考成熟玩法

早期目标是验证玩法结构和乐趣，可以明确借鉴和复刻参考游戏中的机制关系、节奏和数据思路。进入原创内容生产阶段时，再决定哪些内容保留为机制参考、哪些需要替换或重新设计。

## 9. 当前 Game Concept 仍需讨论的问题

### 9.1 阵列探索的最核心乐趣是什么？

需要进一步明确相对于《绝区零》原本阵列模式，我们最希望深入的是哪一部分：

- 信息不完整；
- 路线规划；
- 格子与机关连锁；
- 风险/收益管理；
- 资源消耗；
- 随机事件；
- 地图变化；
- 重复探索与随机生成；
- 或其他机制。

这会决定后续 `exploration-design` 的重点。

### 9.2 主角、装置与机器人之间如何操作？

目前只确定概念关系，尚未决定玩家是在“远程指挥机器人”、直接控制机器人，还是以更抽象的方式操作阵列。

### 9.3 收藏品的意义是什么？

已经确定“探索并带回收藏品”是长期目标之一，但收藏品究竟主要承担：

- 收集展示；
- 解锁新世界泡；
- 叙事记录；
- Meta Progression；
- 玩法能力；
- 或纯粹完成度目标，

仍需后续决定。

### 9.4 一次探索如何结束？

需要确定不同世界泡是否共享某种稳定的结束结构，例如主动撤离、达到出口、完成目标、失败回收等，还是完全由世界泡规则决定。

### 9.5 世界泡切换时，什么东西跨世界保留？

需要进一步定义玩家、机器人、收藏、能力、货币与知识中哪些属于全局层，哪些属于单个世界泡。

## 10. 当前设计方向摘要

当前 Game Concept 可以压缩为：

> **玩家通过一台世界泡观测装置，派遣自动探索机器人进入不同世界泡，在阵列结构中探索、判断与触发事件，并把收藏品和探索成果带回。阵列探索是游戏的长期核心；类幸存者只是当前世界泡首先实现的一种局部玩法，未来其他世界泡可以使用完全不同的地图规则与核心玩法。**
