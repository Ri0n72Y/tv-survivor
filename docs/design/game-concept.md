# Game Concept

> 状态：讨论中。
>
> 本文件描述 **tv-survivor 想成为怎样的游戏**。Design 先于版本 Requirement：Design 可以保留尚未进入当前开发范围的设想；Requirement 在设计收敛后，从 Design 中抽取当前版本要实现的 Scope。
>
> 当前讨论只确认游戏概念与玩法关系，不提前把未来扩展方向实现成通用框架。

## 1. 核心概念

这是一款以 **阵列式模拟宇宙 / 世界泡探索** 为核心 Gameplay 的游戏。

每次探索开始前，玩家从可用角色中选择 **一个角色** 进入模拟宇宙测试。模拟宇宙以“世界泡 / 测试场景”的形式组织不同探索内容；玩家控制所选角色在阵列化结构中移动、调查、读取有限信息、触发事件、管理资源与侵蚀，并在必要时展开当前测试场景对应的局部玩法。

一次探索的核心不是单纯走到终点，而是在不断累积的侵蚀压力下决定路线、处理事件、获取资源、寻找净化与休整机会，并把收藏品和其他探索成果带回据点。

阵列探索是长期稳定的核心。类幸存者战斗、卡牌、搜打撤或其他玩法都属于某个世界泡内部可被阵列事件展开的 **局部玩法**，不等同于游戏本体。

## 2. 角色进入模拟宇宙与最低限度世界设定

当前项目只保留足以支撑玩法的世界设定：

- 游戏支持多个可选角色；
- 每次探索开始前只选择一个角色进入本次模拟宇宙测试；
- 模拟宇宙可以以不同“世界泡 / 测试场景”组织不同空间结构、规则、事件与局部玩法；
- 所选角色保留自己的基础属性、核心武器与角色成长身份；
- 探索过程中再叠加本次 Run 获得的随机武器、被动、资源与其他构筑；
- 探索可以产生收藏品及其他可带回成果；
- 模拟宇宙测试的更完整背景、参与者关系和测试目的暂不展开，除非具体玩法需要。

世界观服务于玩法，不以建立完整宇宙史、势力史或社会结构为前提。

当前第一位正式设计角色为 **开拓者 / 小浣熊**。角色与核心武器的具体规则见 `docs/design/character-design.md`。

## 3. 核心 Gameplay：阵列探索

阵列探索是玩家主要进行判断、资源管理和内容接收的结构层。

主要设计参考为《绝区零》的阵列探索模式，尤其参考早期零号空洞以探索、压力累积、事件与休整构成连续过程的设计；次要参考《魔塔》式格子探索。

阵列层不仅负责连接内容，还负责直接承载：

- 路线与空间判断；
- 有限信息与揭示；
- 侵蚀累积；
- 净化与延缓侵蚀；
- 资源获得、消耗与提交；
- 机关、条件与地图状态变化；
- 随机或条件事件；
- 剧情、演出与世界泡内容表达；
- 局部玩法入口；
- 休整、安全屋与阶段性整备；
- 深入、转向和撤离的选择。

阵列探索不能退化为“在真正玩法之间赶路”的菜单。即使不展开局部玩法，玩家在阵列中的移动和事件处理本身也应持续产生判断、变化与后果。

## 4. 基础压力循环：侵蚀与净化

侵蚀是当前阵列探索的基础核心压力。

玩家在世界泡中推进时会逐渐累积侵蚀。侵蚀使探索天然具有持续成本，并让路线选择不只是“哪边奖励更多”，还包含“还要不要继续深入”。

侵蚀不是单纯倒计时。地图中应存在能够：

- 清除侵蚀；
- 延缓侵蚀；
- 用其他资源交换侵蚀；
- 为高侵蚀提供特殊收益或事件；
- 改变之后侵蚀节奏，

的节点、事件与房间。

因此基础循环是：

```text
进入世界泡
    ↓
探索阵列并累积侵蚀
    ↓
获取信息 / 资源 / 收藏 / 事件
    ↓
决定继续深入、绕行、净化或休整
    ↓
展开必要的局部玩法
    ↓
结果回流到阵列
    ↓
继续探索或结束本次行动
```

## 5. 安全屋与休整节点

阵列中可以存在少量具有明确空间意义的安全场景，例如安全屋。

安全屋的基础特征是：

- 场景内不继续累积侵蚀；
- 玩家可以暂停高压探索节奏；
- 允许进行一定程度的资源提交、整理或升级；
- 可以承载固定剧情、记录、NPC/装置交互或阶段结算；
- 安全本身应是一种稀缺的地图价值，而不是随处可用的菜单功能。

安全屋具体能做什么，由后续 Game Design / Exploration Design 继续确定；System Design 只负责在这些玩法规则进入 Requirement 后决定其软件实现结构。Game Concept 当前只确认它承担 **节奏缓冲 + 安全空间 + 阶段整备** 的职责。

## 6. 地图生成与随机边界

当前正式方向不是完全随机生成主地图。首个世界泡初期预计使用 **配置文件驱动的固定地图** 作为关卡输入；现有随机地图生成算法继续保留为算法能力、测试工具和未来特殊地图实验基础，但不作为当前主地图默认来源。

### 6.1 稳定部分

每一大关的主要地图形状、关键路径关系、空间节奏和重要演出位置应由设计决定。

初期实现优先让这些地图结构从配置文件中加载，使关卡形状能够被明确设计、版本化和重复验证，而不是依赖运行时随机生成器决定主拓扑。

这样可以确保：

- 每关拥有可识别的空间主题；
- 能设计明确的机关与路线关系；
- 能通过阵列本身进行演出；
- 能形成类似《绝区零》芭莱大厦那样依靠格子、视觉、移动和空间关系建立气氛的关卡；
- 重复探索仍保留该关卡自己的记忆点。

### 6.2 随机部分

重复探索的变化主要来自：

- 事件内容；
- 事件出现位置；
- 部分奖励、资源与风险配置；
- 局部玩法组合；
- 特定条件下出现的特殊房间或支路；
- 被明确设计为随机机制的特殊地图形状。

特殊地图形状可以从预先设计的模板中随机，而不是无约束地程序生成任意拓扑。

现有随机地图算法暂不移除。它作为独立算法能力保留，可继续用于测试、特殊地图实验或未来明确选择随机拓扑的世界泡；是否在正式内容中启用由对应 Game Design 决定。

总体原则是：

> **形状负责关卡设计与演出，事件负责重复探索的变化。**

## 7. 阵列演出与视觉方向

阵列模式本身是主要表现媒介之一，不只是功能 UI。

可以参考《绝区零》利用格子、界面状态、异常显示、移动方式和局部视觉变化完成演出的思路，但形成自己的视觉语言。

当前视觉方向为 **赛博显像管风格**：

- CRT / 显像管扫描与发光特征；
- 电子观测设备感；
- 阵列节点像被仪器解析和重建的空间信息；
- 异常、侵蚀、失真可以直接反映在阵列视觉上；
- 不沿用《绝区零》的录像带/录像店符号体系。

阵列视觉可以承担气氛、恐怖、异常、空间错位和叙事表达。某些关卡即使没有大量文字，也应能仅通过地图形状、节点行为、显示异常和移动方式形成鲜明体验。

## 8. 局部玩法

阵列探索过程中可以展开不同类型的局部玩法。

局部玩法是世界泡规则的一部分，而不是阵列系统的固定组成。

当前版本主要实现 **类幸存者** 玩法，但设计上不能假设所有世界泡都会通过类幸存者战斗解决事件。

概念上，阵列层只需要知道：

1. 当前事件需要进入某种局部玩法；
2. 当前世界泡决定使用哪种玩法及其输入条件；
3. 局部玩法结束后返回结果；
4. 结果继续改变阵列探索状态。

具体软件接口、数据契约和模块边界属于后续 System Design 与 Spec，不在 Game Concept 中提前设计。

## 9. 当前主要世界泡：类幸存者原型

当前开发阶段首先制作一个以类幸存者玩法为主要局部玩法的世界泡。

这一世界泡同时验证：

1. 阵列探索本身是否成立；
2. 侵蚀—净化—休整的压力循环是否成立；
3. 阵列事件与局部玩法能否自然展开和回流；
4. 重复探索中固定地图骨架 + 随机事件是否具有足够变化；
5. 类幸存者局部玩法本身是否具有足够可玩性。

本世界泡的类幸存者战斗使用 **同步值（Sync）作为核心生存资源**。同步值取代传统 HP 的角色：受击、信号状态、失联、恢复以及战斗失败压力都应围绕同步关系组织，而不是再并行维护一套独立生命值玩法。同步值的具体消耗、恢复、归零后果和层间继承规则继续在后续设计中收敛。

类幸存者部分主要参考《崩坏：星穹铁道》活动“银河球棒侠传说”的体验方向，在原型阶段可参考其武器、怪物、成长节奏与构筑关系进行玩法验证。**当前代码中的具体武器与被动不作为正式内容保留**；它们主要作为构筑、自动攻击、属性聚合、升级和奖励接入等代码思路与原型验证参考，正式内容后续重新设计。

当前剧情只采用轻量包装：本次探索作为一项模拟宇宙测试展开，其中的测试场景可以继续采用“某个愚者随手丢弃的一份未采用废案”作为世界泡内容来源 / 场景包装。该设定当前只服务于测试场景与玩法表达，不扩展为完整世界观。

## 10. 当前世界泡的内容骨架

当前世界泡先采用最经典、最容易控制节奏的 **三层 / 三大关** 结构。

每一层即一个主要关卡阶段，并拥有独立的最终 Boss。击败本层最终 Boss 后进入下一层；击败第三层最终 Boss 后完成当前世界泡的三层主流程，并进入世界泡结算 / 返回流程。

每一层拥有独立的：

- 主题；
- 视觉与显示特征；
- 主地图形状；
- 路线与机关特色；
- 侵蚀压力变化；
- 独立事件池；
- 特定房间形状；
- 怪物与局部玩法组合；
- 奖励与收藏内容；
- 阶段性演出；
- 最终 Boss 与阶段目标。

三层之间共享同一套基础探索语言，但不应只是数值越来越高的重复地图。

具体内容在 `docs/design/exploration-design.md` 中逐步填充。

## 11. 模拟宇宙测试场景作为内容与玩法容器

“世界泡 / 测试场景”用于解释为什么不同模拟宇宙探索可以拥有显著不同的地图结构、地图生成方式、视觉主题、事件规则、资源风险、局部玩法与收藏内容。

未来候选方向包括但不限于：

- 随机地图生成的阵列探索；
- 打牌爬塔；
- 球比伦式肉鸽；
- 类《小丑牌》的冒险/构筑玩法；
- 搜打撤；
- 其他能够和阵列探索形成输入—结算—回流关系的玩法。

这些目前都是未来 Design 空间，不属于当前版本 Requirement，也不因此要求现在实现支持所有玩法的通用引擎。

## 12. 设计原则

### 12.1 阵列探索优先

评估新增内容时，首先判断它如何丰富阵列探索中的信息、路线、侵蚀、资源、事件、空间状态或演出，而不是先增加新的局部小游戏。

### 12.2 侵蚀必须形成选择

侵蚀应推动玩家改变路线与资源决策，而不是只形成一个等待归零的时间条。

### 12.3 地图骨架服务设计，随机服务重玩

主要空间结构优先手工设计；随机内容用于制造重复探索变化。除非某一关的主题就是空间不稳定，否则不以完全随机地图替代关卡设计。

### 12.4 局部玩法必须回流

局部玩法不能成为与阵列无关的独立关卡。它至少需要接收来自阵列的上下文，并返回能够改变后续探索的结果。

### 12.5 世界泡允许变化，但不提前泛化实现

设计上承认未来存在完全不同的世界泡和玩法；工程上只为当前 Requirement 选中的内容建立必要边界。

### 12.6 世界观服从玩法

只有当设定能够解释、强化或组织玩法时，才在当前阶段展开。

## 13. 当前 Game Concept 仍需讨论的问题

后续主要需要继续确定：

- 侵蚀的具体阶段、阈值与后果；
- 净化事件和净化资源的基本分类；
- 安全屋的固定功能与出现位置；
- 三层各自的主题与空间特色；
- 每层主地图骨架；
- 事件池的分类方式；
- 类幸存者局部玩法从阵列接收哪些状态，又返回哪些结果；
- 第三层 Boss 完成后的结算 / 返回细节，以及主动撤离或失败如何结束本次行动；
- 收藏品与全局进程的关系。

## 14. 当前设计方向摘要

> **每次探索前，玩家选择一个角色进入模拟宇宙测试。测试以世界泡 / 场景形式展开，玩家在由配置驱动的固定关卡骨架和随机事件组成的阵列空间中探索。探索持续累积侵蚀，并通过路线、事件、净化和安全屋管理压力；必要时展开当前测试场景的局部玩法。角色保留自己的基础属性与核心武器，本次 Run 再叠加随机构筑。当前测试场景采用三层三大关结构，每层以最终 Boss 收束并推进到下一层；类幸存者战斗以 Sync 取代传统 HP 作为核心生存资源。现有随机地图算法作为可选算法能力保留，未来其他测试场景可以选择不同地图规则和局部玩法，但阵列探索仍是长期核心。**
