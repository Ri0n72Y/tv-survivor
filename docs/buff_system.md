# Buff 系统约定

当前 buff 系统是轻量战斗组件，不是完整 ECS。Godot 场景仍负责具体玩法表现，buff 系统只集中管理状态数据和结算顺序。

## 组件

- `BuffDefinition`：静态定义，包含 `id`、显示名、图标路径、标签、最大层数、tick 间隔和持续时间。
- `BuffInstance`：运行时状态，包含层数、tick 计时、剩余时间、来源和扩展数据。
- `BuffContainer`：挂在目标上的 buff 列表。目标可以是玩家、敌人或未来的玩法对象。
- `BuffSystem`：统一结算所有已注册容器，在实际 tick 发生时按 `before_tick`、`tick`、`after_tick` 产出事件。

## 结算边界

buff 对象本身不直接扣血、改速度或操作节点。具体效果由玩法场景消费 `BuffSystem.process()` 返回的事件后执行。

这样可以让同一个系统服务玩家和敌人，同时保留 Godot 场景的轻量表达能力。未来 buff 栏也应直接读取 `BuffContainer.get_display_buffs()` 作为展示数据来源。

当前同步相关状态也走这套组件：

- `信号弱`：低信号区结算前叠层，按层数扣同步率，离开后在下一次结算前清零。
- `同步稳定`：不受伤且不处于信号弱或不稳定状态时生效，持续稳定 3 秒后恢复同步率。
