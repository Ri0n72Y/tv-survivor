# PR 契约

## 设计图

首次创建 PR 或引入新模块时，PR 描述必须包含 Mermaid 图。代码导致组件、职责、依赖、输入输出、状态机、生命周期、失败处理或并发/递归规则变化时，必须同步更新。

## 测试同步

每次代码修改后，PR 测试区至少包含：

- 当前 head SHA；
- 本轮行为契约；
- 自动测试；
- 回归测试；
- 人工步骤；
- 每项预期结果；
- 通过/失败/未执行状态。

## 合并原则

- PR 必须基于最新 main，避免隐式覆盖并行功能。
- 有分叉时先比较 main 独有提交，再进行三方合并或重基。
- 冲突解决应记录保留了哪一侧的行为以及原因。
- 未验证的合并必须明确进入后续测试门禁。
